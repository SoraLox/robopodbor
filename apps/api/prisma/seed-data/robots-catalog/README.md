# Каталог роботов — структура данных v2.0.0

187 уникальных роботов из каталога ФЦ БАС, 29 категорий, 103 производителей. Обновлено 2026-09-25.

## Главное правило v2

Всё, по чему фильтруют и ищут, — **код из закрытого списка**, а не свободный текст. Русский текст остался только там, где его показывают как есть: название модели (`name`, `aliases`) и юрлицо (`vendors.legal`). Расшифровка любого кода на русском и английском — в `codes.json`, регионы — в `regions.json`.

Пример: было `"region": "Ярославская область"`, `"type": "Торговля и услуги"`. Стало: регион у производителя `"region": "RU-YAR"`, отрасль у робота `"ind": {"ts": true, ...}`.

## Правила записи

1. ID робота — 2 буквы категории + 4 цифры: `AM0001`. ID производителя — `VN0001`, источника — `SR0001`. ID не переиспользуются.
2. Ключи — английские сокращения в snake_case. Полные названия — в таблицах ниже.
3. Единица измерения — суффикс ключа: `l_mm`, `mass_kg`, `run_min`, `spd_mps`. Значения всегда числа в этой единице.
4. Габариты — отдельные поля `l_mm`, `w_mm`, `h_mm`, никогда не строка `100x100x100`.
5. Диапазон — объект `{"min": ..., "max": ...}`. «до 6 часов» → только `max`. Одно значение → `min = max`.
6. Перечисление (одно значение из списка) — код ЗАГЛАВНЫМИ: `"loco": "WH"`.
7. Набор флагов (несколько значений) — объект со всеми кодами группы строчными: `"sens": {"ld": true, "us": false, "th": null}`.
8. `true` — есть, `false` — источник прямо говорит, что нет, `null` — неизвестно. Пустое поле — всегда `null`, не `0` и не `""`.
9. Ничего не придумано: если значения нет в источнике, поле `null`. У каждого непустого значения есть запись в `sources.json`.
10. Цена `econ.price_rub` — диапазон: в каталоге организатора у трёх роботов разные цены для разных отраслей.
11. Степень защиты IP54 → `env.ip_s = 5`, `env.ip_w = 4` (числа, чтобы фильтровать «не ниже IP54»).
12. Страна производства робота — `origin`; регион и страна компании — в `vendors.json` (связь через `vid`).
13. `search` — служебная строка для поиска: название, другие написания, транслит, производитель, категория. Генерируется, руками не править.
14. `meta.fill_pct` — доля заполненных полей, `meta.n_src` — число источников. Генерируется.

## Как искать и фильтровать

- Список и фильтры: грузите `index.json` (≈190 записей). Мультивыбор — массивы кодов: `scen`, `ind`, `site`, `io`. Фильтр «склад» = `item.site.includes("WH")`.
- Поиск: нормализуйте запрос (нижний регистр, `ё→е`, без пунктуации) и ищите подстроку в `search`. Строка уже содержит кириллицу и транслит, поэтому «rubi» находит «РУБИ-С-03», а «ак sc80» — «АК-SC80». В базе — полнотекстовый поиск PostgreSQL или триграммы `pg_trgm` по тому же полю.
- Карточка робота: `categories.json` → `file` → запись по `id`. Подписи полей — из таблиц ниже или из `description` в JSON Schema.

## Что исправлено по сравнению с v1

- Регион и отрасль были русским текстом — теперь коды (`RU-YAR`, `TS`).
- Производитель был строкой в каждом роботе — теперь отдельная таблица `vendors.json` и ссылка `vid`.
- В юрлице SS0006 «Высoкoтoчные кoмплексы» было 5 латинских «o» — исправлено, кавычки приведены к «ёлочкам».
- «Робот уборщик» / «Робот-уборщик», «Наводная» / «Надводная», пробелы в конце «Сортировка грузов » — подтип организатора заменён нашей категорией, сценарии — кодами.
- Сценарии через запятую («Мониторинг, патрулирование, перевозка грузов») разобраны на отдельные коды; у дублирующихся строк каталога сценарии и отрасли объединены.
- Кириллические буквы в латинских моделях исправлены: `ARIPIX А1` → `ARIPIX A1`, `Supercam Х6М2` → `Supercam X6M2`.
- Грузоподъёмность из названий («Ronavi H1500 (грузоподъемность до 1 500 кг)») вынесена в поле, название очищено.
- Объекты применения `site` — один справочник для всех категорий, чтобы искать «всё для аэропорта» сквозь категории.

## Источники — `sources.json`

`docs` — документы: `sid`, `type` (код `src_type`: OR организатор, VN производитель, RS реселлер, MD СМИ, GV реестр), `title`, `ref` (URL или файл), `pub`, `acc` (дата обращения).

`facts` — по одной записи на значение: `rid` (робот), `path` (поле через точку, например `dims.l_mm` или `nav.sens.ld`), `val`, `sid`, `ok` (true — значение в источнике точное; false — «около», пересчёт л.с., значение серии, а не модели, или выведено), `used` (false — альтернативное значение, в таблицу не попало: конфликт источников), `raw` (цитата из источника), `note`.

Сейчас: 210 источников, 4456 фактов, из них 163 не использованы (конфликты и альтернативы). При конфликте в таблице остаются данные организатора; точное значение вытесняет приблизительное.

Значения `site.*` с пометкой «выведено из сценария организатора» (`ok: false`) поставлены по однозначному сценарию: «Внутрискладская логистика» → склад.

## Как добавить робота

1. Взять `schema/<код>.template.json`, присвоить следующий свободный ID категории.
2. Производитель: найти в `vendors.json` или добавить новый `VN####`.
3. Заполнить только то, что есть в источнике; остальное оставить `null`.
4. Каждое значение записать в `sources.json` → `facts` с цитатой; новый документ — в `docs`.
5. Проверить файл схемой (`jsonschema`, `ajv`) — лишний ключ, строка вместо числа или неизвестный код будут ошибкой.
6. Новый код в справочнике — добавить в `codes.json` и в схему (в исходниках — `spec.py`, затем пересборка).
