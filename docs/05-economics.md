# 5. Экономическая модель (ТЗ 6.5, 3.5)

> Расчётный модуль ведёт отдельная часть команды. Здесь описаны состав показателей, базовые формулы по ТЗ, принятые допущения и то, как результат модели попадает в платформу. Точные формулы и коэффициенты текущей версии модели (`modelVersion`) — в документации модуля и в выгружаемом отчёте.

## Показатели (3.5.2)

| Показатель | Базовая логика | Единица |
|---|---|---|
| Количество роботов | пиковая потребность в операциях / (производительность одного робота × коэффициент загрузки × доступность), плюс резерв | шт. |
| CAPEX | оборудование + инфраструктура + ПО + интеграция + пусконаладка + обучение + резерв | млн ₽ |
| Годовой OPEX | сервис + лицензии + электроэнергия + связь + расходные материалы + ремонт + персонал эксплуатации | млн ₽/год |
| Изменение OPEX | OPEX сценария − OPEX базового сценария, в том числе экономия фонда оплаты труда | млн ₽/год |
| Чистый годовой эффект | сокращение текущих затрат + дополнительный доход или предотвращённые потери − дополнительный OPEX | млн ₽/год |
| Срок окупаемости | CAPEX / годовой эффект, если эффект положительный | лет |
| ROI | накопленный эффект за период / CAPEX × 100% | % |
| TCO | CAPEX + сумма OPEX за горизонт с учётом замены основных компонентов | млн ₽ |

## Сценарии (3.5.5)

- **Как есть** — текущий процесс без роботизации.
- **Покупка** — CAPEX и собственная эксплуатация.
- **Услуга (RaaS)** — аренда: CAPEX минимальный, в OPEX — абонентская плата.

Для каждого сценария показывается чувствительность к стоимости оборудования, объёму операций и стоимости труда (3.5.6). Рекомендация строится не по жёсткому порогу, а по интервалам окупаемости (до 3 лет, 3–5 лет, больше 5 лет) с перечнем рисков (3.5.7).

## Допущения по умолчанию

| Допущение | Значение | Статус |
|---|---|---|
| Ставка дисконтирования | 16% | подтверждено |
| Рост зарплат | 9% в год | подтверждено |
| Горизонт расчёта | 7 лет (ТЗ требует не меньше 5) | подтверждено |
| Обслуживание техники | 7% от цены в год | оценка по данным вендоров |
| Тариф аренды (RaaS) | оценка рынка, 2025 | оценка |
| Стоимость смены оператора | оценка рынка, 2025 | оценка |

Пользователь может менять ключевые допущения на странице результатов: стоимость персонала, режим работы, производительность, стоимость оборудования и обслуживания, коэффициент загрузки, горизонт (3.5.3).

## Входные данные модели

- **Паспорт объекта** — значения полей `ParameterField`. У каждого поля есть единица измерения, допустимый диапазон, значение по умолчанию и источник норматива. Все они видны в форме и попадают в отчёт с пометкой «введено» или «по умолчанию».
- **Характеристики решения** — карточка каталога: цена, стоимость ПО, внедрения и обслуживания, производительность, автономность, срок службы. Поля, по которым приняты допущения, перечислены в `unconfirmedFields` и выводятся в отчёте.
- **Источники** — справочник `DataSource`, он же раздел «Источники» в отчёте.

## Результат и воспроизводимость (3.1.5)

Результат модели — объект `CalculationResult` из контракта: KPI, сценарии, структура затрат, TCO, чувствительность, допущения, а также `dataVersion`, `modelVersion` и `calculatedAt`. Результат сохраняется в проект как снимок:

```http
POST /api/projects/{id}/calculations
{ "calculation": { …CalculationResult… }, "modelVersion": "economics-2026.09", "solutionId": "…" }
```

Паспорт объекта берётся из проекта и сохраняется в снимке вместе с результатом.

Каждый снимок хранится в истории проекта. При повторном открытии показывается сохранённый результат, а не пересчёт, — с указанием версий данных и модели.

## Где пользователь видит формулы и допущения (3.5.8)

- Страница «Методика» (`/methodology`) — описание модели и значения по умолчанию.
- Страница результатов — допущения и структура затрат.
- Отчёт PDF — оговорка о предварительном характере оценки, параметры объекта с происхождением значений, выбранное решение с ограничениями, сценарии, CAPEX и OPEX, допущения, источники, версии данных и модели в колонтитуле.
- Excel — листы «Отчёт», «Сценарии», «CAPEX и OPEX», «Паспорт объекта», «Допущения», «Источники», «Чувствительность».
