# 11. Возможные интеграции (ТЗ 3.8)

Сейчас данные поступают из файлов (Excel/CSV) и встроенной базы. Все операции импорта уже доступны как API (ТЗ 3.8.2), поэтому внешняя система подключается к тем же точкам, что и интерфейс. Описание — в [`contracts/openapi.yaml`](../contracts/openapi.yaml).

| Данные | Точка входа |
|---|---|
| Параметры объекта | `POST /api/object-types/{slug}/parameters/import` (файл) или `POST /api/projects` с полем `parameters` |
| Каталог решений | `POST /api/catalog/solutions/import`, `POST`/`PUT /api/catalog/solutions` |
| Нормативы | `PATCH /api/admin/parameters/{fieldId}` |
| Источники данных | `POST`/`PUT /api/admin/sources` |
| Расчёт по паспорту и решению | `POST /api/calculations` |
| Результат внешней модели | `POST /api/projects/{id}/calculations` |

Для интеграций «сервер — сервер» потребуется отдельный механизм доступа (сервисные токены вместо cookie-сессии). Это первый шаг в плане развития.

## WMS (система управления складом)

- **Что получаем:** фактические объёмы приёмки, отбора и отгрузки по часам, число SKU, структуру ячеек, длину маршрутов. Это точнее ручного ввода паспорта и даёт реальную пиковую нагрузку для расчёта количества роботов.
- **Как:** выгрузка агрегатов из WMS за период, преобразование в поля паспорта `wh_*`, создание проекта через API.
- **Обратно:** требования к WMS со стороны выбранного решения (постановка задач роботам, интерфейс систем управления парком) — из карточки решения, раздел «Интеграция».

## ERP

- **Что получаем:** фонд оплаты труда по подразделениям, стоимость смены, амортизационные политики, ставку дисконтирования компании. Это замена отраслевых оценок в допущениях расчёта.
- **Обратно:** CAPEX и OPEX по годам в разрезе статей из Excel-выгрузки для формирования инвестиционной заявки.

## 1С

- **1С:ЗУП** — численность и стоимость персонала по сменам.
- **1С:Бухгалтерия / 1С:ERP** — тарифы на электроэнергию, фактические расходы на обслуживание текущего оборудования.
- **Как:** регламентная выгрузка в Excel по шаблону паспорта или HTTP-сервис 1С, вызывающий API платформы.

## Системы мониторинга оборудования

- **Что получаем после внедрения:** фактическую производительность, доступность, простои и зарядку роботов.
- **Зачем:** сравнить факт с расчётом, подтвердить или скорректировать характеристики в каталоге (признак «подтверждено») и калибровать веса подбора.
- **Как:** периодическая передача агрегатов (телеметрия по MQTT или REST у поставщика → адаптер → обновление карточки решения с записью в журнал изменений).

## Аналитические продукты ФЦ БАС

- **Каталог:** обмен таблицей решений в формате выгрузки платформы (`GET /api/catalog/solutions/export`) — те же колонки, что и при импорте.
- **Аналитика спроса:** обезличенная статистика проектов — типы объектов, выбранные решения, диапазоны окупаемости. Для этого нужен отдельный агрегирующий API без доступа к проектам пользователей.
- **Госреестры:** проверка российского происхождения по реестру ГИСП и учёт мер поддержки — дополнительная функция 3.8.4, источник уже заведён в справочнике.
