## Известные ограничения

- **Данные каталога.** Каталог роботов (v2.0.0, 187 роботов) заполнен неравномерно. У складских роботов, которые показывает симуляция, чаще всего нет ёмкости батареи или мощности (27 из 34), времени зарядки (18) и времени работы (12): производители их не публикуют. Недостающее симуляция берёт у демо-робота того же типа и перечисляет это у сцены; расчёт экономики не учитывает электроэнергию и помечает это в предупреждении. Фото есть у 31 робота из 74, участвующих в подборе.
- **Упрощения экономики.** Нет дисконтирования и налогов. Робот замещает один пост в каждой смене. Внедрение, обслуживание, аренда и тариф на электроэнергию (один на все регионы) — оценки. Замещаемые роли заданы по процессу: для уборки склада, охраны, инвентаризации, обслуживания пассажиров и пожарной безопасности в паспорте нет персонала, и окупаемость не считается.
- **Симуляция только складская.** Для аэропорта и клиники 3D-сцены нет.
- **Сайт на GitHub Pages без сервера.** Если переменная `API_URL` не задана, сайт работает на встроенных моках: аккаунты, проекты и расчёты хранятся в `localStorage` браузера и не видны с другого устройства. Как подключить настоящий сервер — в [02-deploy.md](02-deploy.md).
- **Удалённые решения каталога** возвращаются при повторном запуске сида (`docker compose up` запускает его каждый раз): сид загружает каталог роботов целиком. Правки администратора в существующих решениях сид не трогает.
- **Роль администратора** назначается запросом к базе, отдельного интерфейса управления пользователями нет.
- **Автоматическое обновление каталога** не реализовано. Обновление выполняется по запросу администратора: вручную или импортом таблицы.
- **Веса ранжирования** — экспертное допущение команды, они не калибровались на реальных внедрениях.
- **Проверки подбора** покрывают ключевые ограничения: груз, проходы, пол, высота, температура, перрон, лифты, бюджет. Более тонкие условия (радиус разворота, уклоны, пропускная способность лифтов) не проверяются и попадают в «Недостающие данные» или в ограничения карточки.
- **Файлы** разбираются в памяти и не хранятся. Исходный файл импорта повторно скачать нельзя, сохраняются только распознанные значения.
- **Масштаб.** Нагрузочный тест на 50 одновременных пользователей (ТЗ 4.3.1) проведён на одном экземпляре API без nginx, результаты — в [03-architecture.md](03-architecture.md). На сервере с другим железом их стоит повторить тем же скриптом. Кеш справочников локален для каждого экземпляра API: при нескольких экземплярах правка видна остальным не позже чем через 60 секунд.

## План развития

1. Получить от ответственного за каталог недостающие характеристики (батарея, зарядка, производительность) и фото, закрыть расхождения, найденные при сверке с открытыми источниками.
2. Расширить экономику: роли персонала для всех процессов, региональные тарифы, дисконтирование для защиты бюджета.
3. Добавить плановое обновление каталога из открытых источников с модерацией изменений через журнал.
4. Добавить роль вендора: поставщик ведёт карточки своих решений, администратор подтверждает изменения.
5. Проверять российское происхождение по реестру ГИСП через API и учитывать меры господдержки в расчёте.
6. Добавить интеграционный API для WMS, ERP и 1С по [11-integrations.md](11-integrations.md).
7. Калибровать веса ранжирования по данным реализованных кейсов.
8. Добавить 3D-сцены аэропорта и клиники.
9. Добавить новые типы объектов (производство, ритейл, агро) данными, без изменения кода.
