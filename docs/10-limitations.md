## Известные ограничения

- **Данные организатора.** Полный каталог организатора и файл цен (catalog_export_v5) загружаются импортом таблицы, как только будут получены. В стартовом каталоге часть характеристик заполнена по открытым источникам и помечена как допущение.
- **Удалённые решения стартового каталога** возвращаются при повторном запуске сида (`docker compose up` запускает его каждый раз). Чтобы убрать решение насовсем, удалите его из `seed-data/solutions.json` или замените импортом.
- **Роль администратора** назначается запросом к базе, отдельного интерфейса управления пользователями нет.
- **Автоматическое обновление каталога** не реализовано. Обновление выполняется по запросу администратора: вручную или импортом таблицы.
- **Веса ранжирования** — экспертное допущение команды, они не калибровались на реальных внедрениях.
- **Проверки подбора** покрывают ключевые ограничения: груз, проходы, пол, высота, температура, перрон, лифты, бюджет. Более тонкие условия (радиус разворота, уклоны, пропускная способность лифтов) не проверяются и попадают в «Недостающие данные» или в ограничения карточки.
- **Файлы** разбираются в памяти и не хранятся. Исходный файл импорта повторно скачать нельзя, сохраняются только распознанные значения.
- **Масштаб.** Нагрузочное тестирование на 50 одновременных пользователей (ТЗ 4.3.1) пока не проводилось. Кеш справочников локален для каждого экземпляра API: при нескольких экземплярах правка видна остальным не позже чем через 60 секунд.

## План развития

1. Загрузить полный каталог и цены организатора, проверить подбор на трёх демо-объектах.
2. Добавить плановое обновление каталога из открытых источников с модерацией изменений через журнал.
3. Добавить роль вендора: поставщик ведёт карточки своих решений, администратор подтверждает изменения.
4. Проверять российское происхождение по реестру ГИСП через API и учитывать меры господдержки в расчёте.
5. Добавить интеграционный API для WMS, ERP и 1С по [11-integrations.md](11-integrations.md).
6. Калибровать веса ранжирования по данным реализованных кейсов.
7. Добавить новые типы объектов (производство, ритейл, агро) данными, без изменения кода.
