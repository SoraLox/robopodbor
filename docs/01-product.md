# 1. Целевая аудитория, сценарии и границы решения (ТЗ 6.1)

## Для кого

- Руководители предприятий и подразделений, которым нужно обосновать бюджет на роботизацию перед инвестиционным комитетом.
- Технические директора, руководители автоматизации и цифровой трансформации.
- Логисты, операционные и финансовые аналитики, готовящие предварительное обоснование.
- Дополнительно — интеграторы и поставщики, которые собирают расчёт для своих клиентов.

Платформа независима от производителей: она не продаёт технику и не получает комиссию за внедрение.

## Пользовательские сценарии

| Сценарий ТЗ | Как реализован |
|---|---|
| 2.1.1 Гость смотрит каталог и делает демо-расчёт | `/catalog`, `/catalog/compare`, мастер `/calculate/:тип` без входа. Незаполненные поля паспорта берутся из датасета организатора, поэтому расчёт работает без ввода данных |
| 2.1.2 Пользователь создаёт проект, вводит или загружает параметры, получает подборку | Паспорт объекта вводится вручную или загружается из Excel/CSV по шаблону. Подбор показывает рекомендованные решения, решения «требует проверки» и исключённые с причинами |
| 2.1.3 Сравнение базового сценария и сценариев покупки и услуги | Страница результатов: сценарии, CAPEX/OPEX, окупаемость, ROI, риски |
| 2.1.4 Имитация работы решения | 3D-симуляция склада на странице результатов по параметрам расчёта и характеристикам выбранного робота |
| 2.1.5 Сохранение и выгрузка | Раздел «Расчёты»: сохранение, копирование, переименование, история расчётов. Отчёт в PDF и расчётные таблицы в Excel |
| 2.1.6 Администратор актуализирует данные | `/admin`: источники данных, нормативы и значения по умолчанию, журнал изменений. `/admin/catalog`: каталог, импорт и экспорт таблицы решений |

Роли: гость, пользователь, администратор (ТЗ 3.1.1). Роль вендора не реализована.

## Типы объектов

Склад, аэропорт и медицинское учреждение. Для каждого типа есть свой паспорт с обязательными и дополнительными полями (склад — 46 полей, аэропорт — 39, медучреждение — 57) и демонстрационный набор значений. Новый тип объекта добавляется данными (запись `ObjectTypeDef` и её поля `ParameterField`), без изменения кода ядра.

## Границы решения

- Это экспресс-оценка, а не проектирование. Результат — гипотеза о целесообразности роботизации и материал для перехода к ТЭО. Каждый отчёт явно помечен как предварительная оценка, требующая верификации при обследовании объекта (ТЗ 3.7.5).
- Интеграции с WMS, ERP, 1С и государственными сервисами не реализованы. Возможные варианты описаны в [11-integrations.md](11-integrations.md).
- Все данные демонстрационного набора обезличены. Реальные персональные данные не используются (ТЗ 4.4.5).
- Демонстрация не зависит от внешних сервисов: каталог, паспорта и демо-расчёт загружаются в базу при первом запуске (ТЗ 4.2.7).
