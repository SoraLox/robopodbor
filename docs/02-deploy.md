# 2. Развёртывание и запуск (ТЗ 6.2, 6.10)

## Требования

- Docker 24+ с Docker Compose v2.
- 2 ГБ свободной памяти, порт 8080.
- Интернет нужен только при сборке образов (npm-пакеты). Во время работы внешние сервисы не нужны.

Пользователю нужен только современный браузер. Специального оборудования и видеоускорителя не требуется.

## Запуск одной командой

```bash
git clone <репозиторий> robopodbor && cd robopodbor
docker compose up --build
```

Что происходит:

1. `db` — PostgreSQL 16, данные хранятся в томе `db-data`.
2. `migrate` — применяет миграции Prisma и заполняет пустую базу: типы объектов, поля паспортов, каталог решений, источники данных, демонстрационные учётные записи. Повторный запуск данные не дублирует.
3. `api` — сервер Express на порту 4000 внутри сети compose. Наружу он не публикуется.
4. `web` — nginx на порту **8080**: раздаёт интерфейс и проксирует `/api` на сервер. Ограничивает частоту запросов: 10 в минуту на вход, 30 в секунду на остальной API.

Проверка готовности: `curl http://localhost:8080/api/health` должен вернуть `{"status":"ok"}`.

Остановка — `docker compose down`. Полный сброс вместе с базой — `docker compose down -v`.

## Настройки

Без файла `.env` поднимаются демонстрационные значения. Для размещения в сети скопируйте `.env.example` в `.env` и задайте значения:

| Переменная | Назначение |
|---|---|
| `POSTGRES_PASSWORD` | пароль базы данных |
| `WEB_ORIGIN` | адрес, с которого открывают интерфейс (для CORS) |
| `DOMAIN` | домен для HTTPS-сертификата (профиль `tls`) |
| `WEB_BIND` | интерфейс, на котором слушает nginx; с TLS — `127.0.0.1` |
| `TRUST_PROXY_HOPS` | число прокси перед API: 1 без TLS, 2 с Caddy |

### HTTPS (ТЗ 4.4.4)

```bash
docker compose --profile tls up -d --build
```

Caddy получает сертификат Let's Encrypt для `DOMAIN` и включает HTTP/2 и HTTP/3. Настройки — в `deploy/Caddyfile`.

## Запуск для разработки

Нужен Node.js 22.

```bash
# API: база из compose, сервер — локально
docker compose up -d db
cd apps/api
printf 'DATABASE_URL=postgresql://robopodbor:robopodbor@localhost:5432/robopodbor\nWEB_ORIGIN=http://localhost:5173\nPORT=4000\n' > .env
npm ci
npx prisma migrate deploy
npx tsx --env-file=.env prisma/seed.ts
npm run dev            # http://localhost:4000

# Интерфейс
cd apps/web
npm ci
npm run dev                             # с моками MSW, без сервера
VITE_ENABLE_MOCKS=false npm run dev     # с настоящим API через прокси /api
```

Порт 5432 наружу не публикуется. Для локальной разработки добавьте `ports: ["5432:5432"]` сервису `db` в `docker-compose.override.yml`.

Проверки: `npm run typecheck`, `npm run lint`, `npm test` (в `apps/web`), `npm run build` (в обоих приложениях).

## Воспроизведение демонстрационного расчёта (ТЗ 6.10)

1. Откройте <http://localhost:8080>, нажмите «Рассчитать» и выберите «Склад».
2. На шаге паспорта нажмите «Скачать шаблон Excel» — это пример файла. Можно ничего не вводить: незаполненные поля берутся из демо-набора, у каждого поля указано значение по умолчанию и его источник.
3. На шаге процессов посмотрите подбор: рекомендованные решения, «требует проверки» и свёрнутый список «Не подходят для объекта» с причинами.
4. Выберите решение и запустите расчёт. На странице результатов — KPI, сценарии «без роботизации», «покупка» и «услуга (RaaS)», структура затрат, чувствительность и визуализация.
5. Выгрузите PDF и Excel кнопками экспорта.
6. Войдите как `krylov@volga-logistic.ru` / `volga123`, пройдите мастер и в разделе «Расчёты» нажмите «Сохранить черновик». В меню строки проекта откройте «История расчётов»: у снимка указаны дата, версия данных и версия модели. Кнопка «Открыть» воспроизводит сохранённый результат.
7. Войдите как `admin@robotopodbor.ru` / `admin123` и откройте «Справочники» в боковом меню, чтобы посмотреть источники, нормативы и журнал изменений.
