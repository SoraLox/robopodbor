# 8. Руководство администратора (ТЗ 6.7, 3.1.4, 3.8)

Вход: `admin@robotopodbor.ru` / `admin123`. В боковом меню появляется блок «Администрирование»: «Редактор каталога» (`/admin/catalog`) и «Справочники и журнал» (`/admin`). Пользователям без роли администратора он не показывается, а API отвечает им 403.

## Справочники

### Источники данных

Список источников, на которые ссылаются каталог, нормативы и отчёт. У источника есть название, область применения, тип (цены, тарифы, реестр, бенчмарк, внедрения, датасет, открытые источники), ссылка, дата актуализации и признак «подтверждён».

- «Добавить источник» — новая запись.
- Карандаш в строке — изменить запись. Корзина — удалить после подтверждения.

Источники выводятся в разделе «Источники» отчёта PDF и на листе Excel.

### Нормативы и значения по умолчанию

Выберите тип объекта. Для каждого поля паспорта можно задать:

- значение по умолчанию — оно подставляется, если пользователь не заполнил поле;
- минимум и максимум;
- источник норматива — показывается пользователю под полем и в отчёте;
- обязательность.

Сохранение проверяет, что минимум не больше максимума и что значение по умолчанию попадает в диапазон. Если нет, показывается ошибка с причиной.

### Журнал изменений

Все правки каталога, нормативов и источников, а также импорты: время, пользователь, действие, краткое описание и таблица «было → стало». Журнал можно отфильтровать по типу записи. Последняя запись определяет текущую версию данных, которая сохраняется в новых расчётах.

## Каталог решений

«Редактор каталога» в меню «Администрирование» или под аватаром в шапке (`/admin/catalog`). Поля, заполненные оценкой команды, помечены «допущение»; правка администратора заменяет оценку и помечается «изменено вручную».

- **Таблица** — все решения с типом, ценой, полнотой карточки и подтверждённостью данных. Справа — дерево «объект → процесс → тип решения».
- **Добавить позицию или «Редактировать»** — форма со всеми группами полей таблицы 3.3 ТЗ:
  - идентификация;
  - технические характеристики;
  - ограничения для подбора: ширина прохода, ровность пола, высота, температура, лифты, допуск на перрон;
  - инфраструктура;
  - экономика;
  - применимость;
  - качество данных.

  Список процессов зависит от выбранных типов объектов. Полнота карточки пересчитывается при вводе. Обязательные поля и числа проверяются до сохранения.

  Поля каталога роботов:
  - **Категория каталога** — код из 29 категорий (FC, AM, FL…), по ней роботы делятся на подкатегории при выборе.
  - **УГТ** — уровень готовности технологии, 1–9.
  - **Типы объектов и основание** — для каждого объекта: «не подходит», «заявлено в каталоге», «пример организатора» или «выведено по сценариям». «Выведено» понижает статус подбора до «Требует проверки».
  - **Фото** — имена файлов из `apps/web/public/robots_photo`, первое — главное. После добавления файлов запустите `bash scripts/build-robot-previews.sh` в `apps/web`.

  Изменённые поля получают источник «правка администратора» — в карточке они помечены «изменено вручную». Повторный сид не перезаписывает правленые характеристики, применимость, процессы и фото.
- **Каталог роботов** — панель над таблицей: текущая версия каталога и загрузка новой версии папкой с предпросмотром изменений. Порядок и правила — в [06-data.md](06-data.md).
- **Удалить** — после подтверждения.
- **Загрузить xlsx / csv**, **Выгрузить xlsx**, **CSV** — работа с таблицей решений, порядок описан в [06-data.md](06-data.md). В таблице есть колонки «Категория каталога», «УГТ», «Фото» и «Основание применимости» в виде `Склад: заявлено в каталоге; Аэропорт: пример организатора` — выгрузка и обратная загрузка их не теряют.

Изменения видны пользователям сразу: кеш справочников сбрасывается при каждой правке.

## Учётные записи

Пользователи регистрируются сами на странице входа и получают роль `user`. Роль администратора назначается в базе:

```bash
docker compose exec db psql -U robopodbor robopodbor \
  -c "UPDATE \"User\" SET role='admin' WHERE email='name@example.ru';"
```
